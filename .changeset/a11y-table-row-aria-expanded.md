[feat] Table tree plugin (`useTableTreeData`) is a WAI-ARIA treegrid. When any row is expandable the table carries `role="treegrid"`, and body rows carry `aria-level`, `aria-expanded` (parents only), `aria-posinset` and `aria-setsize` — the row ARIA axe flagged as invalid on a native table (`aria-conditional-attr`) is now valid in context. Rows also gain a keyboard model with row focus, following the APG treegrid pattern: the visible rows share one roving tab stop that follows focus onto a row (arrow keys, a click, programmatic focus), ArrowUp/ArrowDown move between rows, ArrowRight expands a collapsed row, ArrowLeft collapses an expanded row, Home/End jump to the ends, and Enter/Space toggle an expandable row. ArrowRight on an expanded row and ArrowLeft on a collapsed or leaf row keep focus on the row rather than jumping to a child or parent. Controls inside cells (the chevron, a selection checkbox, a sort header) stay in the Tab order with their own keys untouched, and the chevrons and header expand-all toggle now draw the shared focus ring. This first version is row focus only: cell-by-cell navigation is not implemented, and a composition that needs it is outside the supported contract. Flat data is untouched: no role, no row ARIA, no tab stop. Two consequences worth knowing: a tree table now takes one Tab stop for its rows, at the active row's place in DOM order (Tab order: the scroll region while the table overflows horizontally, the header controls, then the in-cell controls and the active row in DOM order), and a test that queried `getByRole('table')` on a tree table queries `treegrid` now. Also new: `TableRenderProps.ref` lets a plugin reach the `<table>` node (merged with the consumer's `ref`), `TableTreeRowMeta` gains optional `posInSet`/`setSize`, and `useTreeFocus` resolves the focused item through `itemSelector`, so it composes onto hosts whose items are not `role="treeitem"`.
