[feat] Table tree plugin (`useTableTreeData`) is a WAI-ARIA treegrid. When any row is expandable the table carries `role="treegrid"`, and body rows carry `aria-level`, `aria-expanded` (parents only), `aria-posinset` and `aria-setsize` — the row ARIA axe flagged as invalid on a native table (`aria-conditional-attr`) is now valid in context. Rows also gain a keyboard model with row focus: the visible rows share one roving tab stop, ArrowUp/ArrowDown move between rows, ArrowRight expands a collapsed row or enters its first child, ArrowLeft collapses an expanded row or moves to the parent, Home/End jump to the ends, and Enter/Space toggle an expandable row. Controls inside cells (the chevron, a selection checkbox, a sort header) stay in the Tab order with their own keys untouched. This first version is row focus only: cell-by-cell navigation is not implemented, and a composition that needs it is outside the supported contract. Flat data is untouched: no role, no row ARIA, no tab stop. Two consequences worth knowing: a tree table now takes one Tab stop for its rows ahead of the in-cell controls, and a test that queried `getByRole('table')` on a tree table queries `treegrid` now. Also new: `TableRenderProps.ref` lets a plugin reach the `<table>` node (merged with the consumer's `ref`), `TableTreeRowMeta` gains optional `posInSet`/`setSize`, and `useTreeFocus` resolves the focused item through `itemSelector`, so it composes onto hosts whose items are not `role="treeitem"`.
