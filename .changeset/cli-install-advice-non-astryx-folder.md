[fix] The daily hint, the setup reminder, the update notice, `astryx doctor`'s version-alignment and integration fixes, and `astryx discover`'s install command for an integration installed for the computer no longer add a package to a `package.json` that is not an Astryx project's. The project is the one `spec:AST-040` FR9 finds: the nearest folder whose `package.json` declares an Astryx package, or a member its workspace lists, never the home folder and never past a repository root. Run from a folder inside such a project whose own `package.json` is not the project's, such as a tool folder that installs its own `@astryxdesign/core`, the daily hint that matches a project's CLI to its Core, the setup reminder and `astryx doctor`'s version-alignment fix used to name a command that added the CLI to that folder's `package.json`, making it a separate Astryx project. They now compare the CLI with the Core the run reads, as before, and when the two differ they say to run from the project's folder, or to declare an Astryx package in that folder; the update notice upgrades the project from its folder, with the project's release. For an integration installed for the computer, `astryx discover` gives no install command from such a folder, and `astryx doctor`'s fix says to run from the project's folder, where the command adds it for the project; in a folder that belongs to no project, neither names a command. The official packages `astryx discover` lists and the theme packages `astryx doctor` suggests still use the folder the command runs in. A member its workspace lists keeps its own advice. In a folder that belongs to no Astryx project, the hint, the setup reminder and the update notice no longer print, and `astryx doctor`'s fix says how to reach a project. In a folder whose `package.json` declares an Astryx package, the advice is unchanged. No JSON shape or exit code changes.
