[experimental] Icon sets: authoring a set from a library takes fewer steps and fewer guesses. Only the experimental icon commands, the icon-set guide, and `astryx template` in a project that sets `experimental.iconSet` change; every stable command reads exactly as before without the opt-in.

- **`experimental icon new-set`.** `--from` maps a definition only when an icon has its exact name and lists those entries for review; other likely icons come back as at most three suggestions per definition, never written. It records the library and version as `source`, copies the library's license notices and takes its license, keeps `--exclude` in the data file's `exclude` for every refresh, and names the exports it left out as not icons. It writes only the set's own files: its receipt names, as text to copy, the entry change that makes the set's icons import from the package by name (never editing a built or CommonJS entry), the `react` and optional `@types/react` and `@astryxdesign/cli` peers, and the `typecheck` script the package is missing, and `integration check` names the same entry change, once, until it is made. `--variants` and `--default` declare variants; `--display-name` and `--description` fill the descriptor, on a refresh too; a refresh that first records the library also copies its license notices and takes its license. Ids keep a dimension as one word (`squares-2x2`), a library's other names for an icon become its words, and `…Provider` and `…Context` exports are never icons. A library of 1,600 icons is read in about two seconds.
- **`experimental icon add` and `map`.** `add --variant <name> --from <module> --all` adds a variant for every icon at once; `add --id <id> --remove` takes an icon out with its variants, map entries, and generated exports; a `./` file is named as written, and the receipt names the package.json `files` that publishes it. `map --pairs a=b,c=d` writes many entries in one checked write, and both accept a definition's kebab id; `map` names an icon by its id, its export name in any case, or another name its library exports it as, never by one word of its id.
- **All or nothing.** When `new-set`, `add`, `map`, or `new-definition` fails partway, every file is as it was and the error is `ERR_WRITE_FAILED`.
- **Listing.** `experimental icon --set <set> --all-icons` lists every icon of a set (`icon.setIcons`) and `--definitions` lists every Astryx definition, built in or optional (`icon.definitions`). Search shows partial matches only when nothing better matches.
- **Templates.** A mapped icon drops the library's sizing props (`size`, `strokeWidth`, `absoluteStrokeWidth`), reported as `dropped`, and comments on a rewritten import line are kept.
- **Definitions.** Thirteen new icon definitions (`rotate`, `flipHorizontal`, `flipVertical`, `alignLeft`, `alignCenter`, `alignRight`, `panelLeft`, `panelRight`, `gitBranch`, `gitFork`, `scale`, `cpu`, `textCase`), declared by the templates that draw them, and more common glyph names in built-in definitions' words.
- **Checks.** `integration check` suggests icons by the same rule and lists each optional definition with its description and words; the version-drift warning gives the refresh command.
