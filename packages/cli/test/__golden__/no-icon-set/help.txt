Usage: astryx [options] [command]

Design system CLI — components, themes, and tooling

Options:
  -V, --version                     output the version number
  --zh                              Simplified Chinese for component reads and for docs topics that have a translation (English otherwise)
  --dense                           Token-efficient dense text for component <Name> and docs <topic> reads
  --lang <locale>                   Language or format for component and docs reads: en (default), zh (as --zh), or dense (as --dense) (choices: "en", "zh", "dense")
  --detail <level>                  Detail level for component, hook, and docs tree reads (e.g. docs cli/commands/build), and for theme build reports. Lists default to brief; theme build prints one line per built theme unless full, which adds the install example and font recipe (choices: "full", "compact", "brief", default: "full")
  --json                            Output as typed JSON. Success envelope: { apiVersion, type, package?, data, meta? }. Error envelope: { apiVersion, error, code, suggestions? }.
  -h, --help                        display help for command

Commands:
  init [options]                    Initialize the design system in your project
  component [options] [names...]    List components or print component docs
  docs [options] [topic] [section]  Print reference docs
  blog [slug]                       Read the Astryx blog from the published feed
  swizzle [options] [component]     Copy component source for customization
  gap-report [options] [component]  Report a missing component or feature to the package that owns it
  template [options] [name] [path]  List, show, or scaffold page and block templates
  upgrade [options]                 Update your code after upgrading Astryx, and refresh ShadCN-copied components
  theme                             Add, switch, build, and author themes
  integration                       Author and verify an Astryx integration package
  hook [options] [name]             List hooks or print hook docs
  discover [options] [query]        Browse and search integrations: the ones you have and the ones you could add
  search [options] <query...>       Search components, hooks, docs, templates, and themes in one ranked list
  build [options] [query]           Build a page: the template to start from, or the workflow playbook (no query)
  doctor [options]                  Diagnose Astryx projects and integration packages
  manifest                          Print the full CLI capability manifest (use with --json)
  help                              Show all commands

Output format
Text mirrors --json (the machine-readable surface); it is built from these blocks:

block: Record
shape: aligned "key: value" lines = one item; records separated by a blank line

block: Section
shape: a header line (no "key:"), optional one-line subtitle, then its records/list

block: List
shape: "- value" lines for a simple sequence of values

block: Text
shape: free-form prose / notes

block: Code
shape: a verbatim block (source, skeleton, or doc), emitted exactly

Grep a field across records, e.g.  pnpm exec astryx search button | grep "^command:". Errors/warnings go to stderr; use --json for structured parsing.

Global mode: in a project, the project's own CLI answers (this copy hands the run to it); a copy installed for the computer checks for updates once a day and keeps an agent skill in your home folder. See pnpm exec astryx docs global.
